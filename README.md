# Радар тем «Медиастазы»

Редакционная база больших расследований и коротких роликов. Открытые сигналы сгруппированы по тематике канала. Из новости, запроса, видео, статьи или тематической подборки можно создать редактируемую карточку с исходными ссылками.

## Работа с радаром

- В карточке указываются вопрос, соответствие каналу, аудитория, гипотеза, способ проверки и видеоряд. Для большого выпуска оценка складывается из пяти взвешенных критериев. Для коротких роликов работают четыре равных критерия.
- Редакторские карточки, заметки, оценки, избранное и изменения этапов остаются в браузере. Кнопки «Выгрузить» и «Импорт» позволяют перенести базу. Поддерживаются выгрузки предыдущей версии. Сайт и файлы репозитория общедоступны. Чтобы изменить общую стартовую базу, обнови `site/data/topics.json` в репозитории.
- Новостные ленты и публикации ведомств поступают с прямыми ссылками. При совпадении по ключевым словам за 72 часа у двух разных источников появляется тематическая подборка. Такие совпадения требуют редакторской проверки.
- Google Trends показывает приблизительные объёмы всплесков запросов в России и США. Вордстат доступен по ссылке для ручной проверки.
- Видео берутся из открытых лент перечисленных каналов. Сравнение внутри каждого формата идёт по опубликованному счётчику просмотров. Лента содержит только недавние загрузки и может обновлять счётчики с задержкой. Пригодность видео как примера проверяется редактором.
- Crossref возвращает метаданные журнальных статей и ссылки по DOI. Тип записи сам по себе не устанавливает качество исследования.

## Запуск

Требуется Python 3.12. Сторонних пакетов и ключей доступа нет.

```bash
python scripts/collect.py
python scripts/validate.py
python -m http.server 8000 --directory site
```

Открой [локальный сайт](http://localhost:8000/). Настройка источников, рубрик и словарей хранится в `scripts/sources.json`. Сборщик повторяет временно неудачные запросы, сохраняет недавние записи при сбоях и помечает их в состоянии источников. Если недоступны все источники, проверка останавливает публикацию и прежний сайт продолжает обслуживаться.

## GitHub Pages

1. Загрузи проект в ветку `main`. Для нового репозитория используется штатная публикация GitHub Pages через GitHub Actions.
2. В настройках репозитория открой **Pages → Build and deployment → Source → GitHub Actions**.
3. В разделе **Actions** открой «Сбор сигналов и публикация радара» и запусти его вручную. После успешного задания `publish` адрес появится в **Settings → Pages**.
4. Плановые запуски выполняются в 05:23, 11:23, 17:23 и 23:23 по Москве. Обновляется папка `site`. Еженедельная отметка об успешном плановом запуске поддерживает активность репозитория. GitHub может задерживать запуски, а в общедоступном репозитории после 60 дней без активности отключает расписание. При необходимости включи его через **Actions**.
